## 3. 為什麼越聊越貴、越容易忘

### 原因一：每一輪都把之前的對話再送一次
對話一輪一輪進行時，每則使用者訊息和 AI 的回應都會累積在上下文視窗裡，之前的輪次完整保留 [S1]。
每一輪的輸入 = 之前所有對話歷史 + 這次的訊息；這輪的輸出又會變成下一輪輸入的一部分 [S1]。

| 第幾次請求 | 送進去的內容 |
|---|---|
| 第 1 次 | System + User(1) + Asst(1) + User(2) [S5] |
| 第 2 次 | System + User(1) + Asst(1) + User(2) + Asst(2) + User(3) [S5] |
| 第 3 次 | System + User(1) + Asst(1) + User(2) + Asst(2) + User(3) + Asst(3) + User(4) [S5] |

> 圖：三根長條，一根比一根高，代表每次請求的輸入越疊越長。

所以不相關的舊對話不只佔位置，而且每送一則訊息都在花 token [S2]。

### 原因二：塞越多，越抓不到重點（context rot）
token 越多，模型的準確度和回想能力（recall）就會下降，這個現象叫 context rot（上下文腐化）[S1]。
因此「挑選放進 context 的內容」跟「視窗有多大」一樣重要 [S1]。
舊對話還會擠掉你接下來真正需要的檔案 [S2]。

### 視窗快滿了怎麼辦？壓縮（compaction）
壓縮會自動把對話較早的部分摘要起來，讓對話可以超過視窗上限繼續進行 [S1]。
Claude Code 在接近上限時會自動壓縮，所以視窗滿了不會讓 session 結束 [S2]。

| Claude Code 範例 session | 使用中的 token |
|---|---|
| 壓縮（/compact）之前 | 22,225 [S2] |
| 壓縮之後 | 17,095 [S2] |
| 其中：對話摘要 | 1,725 [S2] |

代價是細節會被摘要掉：只在對話裡講過的指示，要寫進 CLAUDE.md 才會在壓縮後保留下來 [S3]。
