## 1. AI 的記憶其實只有一個地方：上下文視窗

上下文視窗（context window）是模型產生回應時能參考的所有文字，包含它正在寫的回應本身 [S1]。
它不是模型訓練時讀過的那一大堆資料，而是模型的「工作記憶（working memory）」[S1]。
換句話說，AI 回答時能參考的，就只有視窗裡的文字 [S1]。

在 Claude Code 裡，這個視窗裝著你的指示、它讀過的檔案、它自己的回應，還有從沒出現在終端機畫面上的內容 [S2]。

### 什麼東西會被算進去？
送出一次請求時，system prompt、每一則訊息（包括工具結果、圖片、文件）和工具定義，通通都算進視窗 [S1]。
連這一輪 Claude 產生的輸出（包括 extended thinking）也算 [S1]。

| 視窗裡的東西（Claude Code 範例 session） | 大約佔多少 token |
|---|---|
| System prompt | 4,200 [S2] |
| 專案 CLAUDE.md | 1,800 [S2] |
| 讀一個檔案 src/api/auth.ts | 2,400 [S2] |
| 你打的第一句 prompt | 45 [S2] |

> 圖：一個大方塊代表視窗，由下往上堆 system prompt、指示檔、對話、讀進來的檔案；方塊頂端標「上限」。

### 視窗有多大？
容量用 token 計算，依模型不同，最多可以到 1M tokens [S1]。
如果光是輸入就已經超過視窗，API 會直接回傳 400 錯誤 [S1]。
不過視窗大不代表塞越多越好，context 越多不一定越好 [S1]（第 3 節會解釋原因）。
