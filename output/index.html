AI 是怎麼「記憶」的？
以 Claude 為例，順便看 token 怎麼被吃掉

主線一句話：AI 記住的東西，最後都要放進 context window（上下文視窗）才有用；放得越多，token 就耗得越多。

1AI 的記憶其實只有一個地方：上下文視窗

上下文視窗（context window）是模型產生回應時能參考的所有文字，包含它正在寫的回應本身S1。 它不是模型訓練時讀過的那一大堆資料，而是模型的「工作記憶（working memory）」S1。 換句話說，AI 回答時能參考的，就只有視窗裡的文字S1。

在 Claude Code 裡，這個視窗裝著你的指示、它讀過的檔案、它自己的回應，還有從沒出現在終端機畫面上的內容S2。

什麼東西會被算進去？

送出一次請求時，system prompt、每一則訊息（包括工具結果、圖片、文件）和工具定義，通通都算進視窗S1。 連這一輪 Claude 產生的輸出（包括 extended thinking）也算S1。

視窗裡的東西（Claude Code 範例 session）大約佔多少 token
System prompt4,200S2
專案 CLAUDE.md1,800S2
讀一個檔案 src/api/auth.ts2,400S2
你打的第一句 prompt45S2

視窗有多大？

容量用 token 計算，依模型不同，最多可以到 1M tokensS1。 如果光是輸入就已經超過視窗，API 會直接回傳 400 錯誤S1。 不過視窗大不代表塞越多越好，context 越多不一定越好S1（第 3 節會解釋原因）。

2三種記憶一次看懂

記憶類型Claude 的例子存在哪、誰寫什麼時候進到視窗
對話內記憶上下文視窗本身每一輪的輸入都包含之前所有對話歷史S1一直都在，直到滿了被壓縮S2
跨對話記憶聊天記憶、搜尋過去對話Claude 在聊天時把記憶存成一個個主題S4搜尋舊對話時以工具呼叫的形式出現S4
外部檔案記憶CLAUDE.md、自動記憶CLAUDE.md 由你寫，自動記憶由 Claude 寫S3你還沒打字前就載入 contextS2

為什麼需要「跨對話」和「外部檔案」？

因為每個 Claude Code session 都是從一個全新的上下文視窗開始S3。 CLAUDE.md 和自動記憶就是用來把知識帶到下一個 session 的S3。 聊天 App 這邊也一樣：S4 形容有了記憶之後，Claude 從無狀態（stateless）的聊天介面，變成會隨時間累積理解的合作者S4。

關鍵：最後都要放進視窗

搜尋舊對話的結果是以工具呼叫的形式出現在對話中S4，而工具結果本來就會算進上下文視窗S1。 CLAUDE.md、自動記憶、MCP 工具名稱和 skill 說明，在你打字之前就已經載入 contextS2。

3為什麼越聊越貴、越容易忘

原因一：每一輪都把之前的對話再送一次

對話一輪一輪進行時，每則使用者訊息和 AI 的回應都會累積在上下文視窗裡，之前的輪次完整保留S1。 每一輪的輸入 = 之前所有對話歷史 + 這次的訊息；這輪的輸出又會變成下一輪輸入的一部分S1。

第幾次請求送進去的內容
第 1 次System + User(1) + Asst(1) + User(2)S5
第 2 次System + User(1) + Asst(1) + User(2) + Asst(2) + User(3)S5
第 3 次System + User(1) + Asst(1) + User(2) + Asst(2) + User(3) + Asst(3) + User(4)S5

所以不相關的舊對話不只佔位置，而且每送一則訊息都在花 tokenS2。

原因二：塞越多，越抓不到重點（context rot）

token 越多，模型的準確度和回想能力（recall）就會下降，這個現象叫 context rot（上下文腐化）S1。 因此「挑選放進 context 的內容」跟「視窗有多大」一樣重要S1。 舊對話還會擠掉你接下來真正需要的檔案S2。

視窗快滿了怎麼辦？壓縮（compaction）

壓縮會自動把對話較早的部分摘要起來，讓對話可以超過視窗上限繼續進行S1。 Claude Code 在接近上限時會自動壓縮，所以視窗滿了不會讓 session 結束S2。

Claude Code 範例 session使用中的 token
壓縮（/compact）之前22,225S2
壓縮之後17,095S2
其中：對話摘要1,725S2

代價是細節會被摘要掉：只在對話裡講過的指示，要寫進 CLAUDE.md 才會在壓縮後保留下來S3。

4Claude 實例 A：聊天 App 怎麼記住你

記憶（memory）：把你的事記成一個個主題

Free、Pro、Max、Ultra 方案的記憶預設是開啟的S4。 Claude 會在聊天過程中把記憶存成一個個主題，而不是等對話結束後才做摘要S4。 它會自己判斷要存什麼，你也可以直接說「remember this」叫它存S4。 每個專案（project）有自己的記憶；在專案裡，Claude 會用專案記憶加上專案外的聊天記憶，但不會用其他專案的記憶S4。

它會記的東西像是：你的角色、專案和工作背景S4。 健康、宗教、政治等敏感主題預設不存S4；而有些資訊（例如政府身分證號、金融帳號）就算你要求也不會存S4。 你可以在設定裡打開任何一個主題來看、編輯或刪除S4。

三種功能比一比

功能做什麼誰能用／怎麼用
記憶把重要資訊存成主題，帶到新對話S4Free、Pro、Max、Ultra 預設開啟S4
搜尋過去對話用 RAG（檢索增強生成）找舊對話，以工具呼叫的形式出現S4付費方案S4
無痕聊天不存進記憶，也不存進聊天紀錄S4所有人都能用S4
單次關閉記憶這次對話不用記憶、也不存記憶，但對話仍留在聊天紀錄S4必須在送出第一則訊息前關掉S4

5Claude 實例 B：Claude Code 的 CLAUDE.md 與自動記憶

每個 Claude Code session 都是從全新的上下文視窗開始S3，所以要靠兩種「寫在檔案裡的記憶」把知識帶到下一次。

兩種檔案記憶

CLAUDE.md 是你寫給 Claude 的指示檔，Claude 在每個 session 開始時都會讀S3。 自動記憶（auto memory）則是 Claude 根據你的更正和偏好，自己寫給自己的筆記S3。

CLAUDE.md自動記憶
誰寫你S3ClaudeS3
內容指示與規則S3學到的東西與模式S3
什麼時候載入每個 sessionS3只載入 MEMORY.md 的前 200 行或 25KBS3
適合放程式規範、工作流程、專案架構S3你的偏好、你給過的更正S3

自動記憶的筆記分成四種：user、feedback、project、referenceS3。 它用 MEMORY.md 當索引，細節寫在一個個主題檔；主題檔不會在啟動時載入，需要時才去讀S3。 Claude 會把詳細筆記移到主題檔，讓 MEMORY.md 保持精簡S3。

開工前就先吃掉的 token

你還沒打字之前，CLAUDE.md、自動記憶、MCP 工具名稱和 skill 說明就已經載入 contextS2：

啟動時載入的東西token
System prompt4,200S2
專案 CLAUDE.md1,800S2
自動記憶 MEMORY.md680S2
Skill 說明450S2
使用者層級 ~/.claude/CLAUDE.md320S2
環境資訊280S2
MCP 工具名稱120S2

寫 CLAUDE.md 的三個提醒

  • 每個 CLAUDE.md 建議少於 200 行，越長越吃 context，也越不容易被遵守S3。
  • CLAUDE.md 是 context，不是強制設定；要強制擋住某個動作，要用 PreToolUse hookS3。
  • 如果專案已經有 AGENTS.md，可以在 CLAUDE.md 裡匯入它，Claude 就會讀 CLAUDE.md 並透過匯入包含 AGENTS.mdS3。

提示快取（prompt caching）：重送的部分打折

第 3 節說過每一輪都會重送之前的對話；prompt caching 的做法是：如果 prompt 開頭那段最近已經快取過，就直接用快取版本，減少處理時間和成本S5。 快取預設可以活 5 分鐘，每次被用到都會免費刷新S5。 多輪對話開啟自動快取時，快取點會隨著對話自動往前移S5。

動作價格（相對於一般輸入 token）
寫入快取（5 分鐘）1.25 倍S5
寫入快取（1 小時）2 倍S5
從快取讀取0.1 倍；Opus 5.5、Sonnet 5.5 是 0.05 倍S5

想讓快取發揮作用：把固定不變的內容放在 prompt 開頭S5，也不要隨便改工具定義，因為那會讓整個快取失效S5。

但要注意：快取只改變你付多少錢，不會讓這些 token 不算進上下文視窗S1。

🥚 做這一頁本身花了多少 token？

這一格是本作業自己的執行紀錄（wiki/log.md、docs/05-token-log.md），不是 S1–S5 的內容。token 數是用讀寫的字元數估算的。

約 8 萬從抓資料到 6 節寫完（估算）
約 5 萬最耗的一步：Ingest 5 份資料
6 次關卡 2 來源檢查 FAIL（6 節各 1 次）
3 處檢查器沒抓到、靠人工複讀才發現的語意錯誤

最常出錯的是「沒標來源的總結句」和「自己加的推論」：這兩種剛好就是 AI 最容易順手補上的東西。
